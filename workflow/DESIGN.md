# Loop / Graph 設計說明

## 使用的模型
Claude Sonnet 5.5（claude.ai 對話介面）。本專案所有 Wiki 撰寫、簡報生成、檢查腳本與測試皆由該模型在同一對話中完成；沒有使用第二個模型做獨立驗證，這是限制（見 tests/run-log.md）。

## 會重複執行的步驟
- 來源取得 → 登錄 → G1：每新增一個來源就跑一次。
- 寫頁 → G2/G3 → 人工抽查：每新增或修改一頁就跑一次。
- 簡報 → G4 → G5 → G6：Wiki 或簡報有任何變動就整組重跑。
- 新事件進來：回到 A，只動 incidents/ 與相關概念頁的連結，不重建整份 Wiki。

## 檢查節點與通過條件
| 節點 | 工具 | 通過條件 | 失敗回到 |
|---|---|---|---|
| G1 來源 | check_sources.py | 必填欄位齊全；id 不重複；事實依據來源必須是官方或標準且全文已讀；媒體不得為事實依據 | 登錄來源 |
| G2/G3 Wiki | check_wiki.py | frontmatter 完整；sources 都存在且為事實依據；正文來源 id 都存在；[事實] 行有來源 id；事件頁明寫「攻擊者身分」「調查進度」 | 重寫該頁 |
| 人工抽查 | 人 | 隨機 3 個 [事實] 句，原文確實這樣說 | 重寫該頁並重讀來源 |
| G4 對應 | check_slides.py | 每頁有教學目的、data-wiki、data-src；Wiki id 存在；來源為事實依據；頁面重要數字都出現在引用的 Wiki 頁；無外部資源 | 修簡報（若是 Wiki 錯則回 Wiki） |
| G5 導覽 | test_nav.js | 換頁、邊界、進度條、目錄、hash、按鍵、滑動邏輯正確 | 修簡報 |
| G6 問答 | run_qa.py | 有答案的題目能在指定頁檢索到預期內容；Wiki 沒有的題目，Wiki 必須明確寫「未載」 | Wiki 缺內容→回寫頁；測試有誤→修測試 |
| G7 真實瀏覽器 | 人 | 桌面與手機畫面無破版、可換頁 | **本次未執行** |

## 為什麼這樣設計
- 問題多半發生在「來源 → 陳述」的對應，所以檢查放在寫頁之後、簡報之前；簡報只能引用已通過的 Wiki。
- 回退規則：問題發生在哪一層就回哪一層。簡報裡的數字錯，先查 Wiki 是否錯；不在簡報表面改數字。
- 機械檢查便宜、可重複，但看不出語意錯誤，所以保留人工抽查。

## v1 → v2 修改（依第一次實際執行結果）
1. G3 新增規則：事件頁必須明寫「攻擊者身分」「調查進度」。原因：G6 的 Q6、Q7 第一次失敗，Wiki 對未知事項沉默。檢查因此由 G6 前移到 G3（並寫入模板與 AGENTS.md）。
2. 來源取得加上「讀不到或網址被拒 → 改搜尋取得網址」迴圈。原因：多次直接 fetch 未出現過的網址被拒。
3. 「寫頁前重讀來源全文」寫進 AGENTS.md。原因：早期頁面曾引用已無法覆核的來源，或過度陳述。
4. 新增人工抽查節點。原因：機械檢查抓不到語意錯誤。

## 未來重複使用
新事件依 AGENTS.md §6 的 SOP 進行；五個檢查指令不需修改；模型更換時重跑 G6 並記錄。
